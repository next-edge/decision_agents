# Decision Agents

## 背景

* 近年、LLMモデルを単に１対１で対話するのではなく、専門性や固有の目的を持つ複数の異なるエージェントを事前に定義することにより、複数のエージェントと連携を取るマルチエージェントの仕組みが注目されている。

* 本プロジェクトでは、実際に新規事業を構想するスタートアップ企業という具体的なユースケースを設定し、少数の創業者や起業家にとって、マルチエージェントのプログラムが意思決定において有益となるのか検証したいと思う。

## 目的

* 新規事業を構想するスタートアップ企業にとってマルチエージェントの仕組みが有益かを検証すること。
* マルチエージェントのプログラムにおいて、プロンプト（instructions）等の設定値がどれだけ成果物の精度に影響するのかを実験を通じて検証すること。

## 本プロジェクトの位置づけ

* 本プロジェクトはプロトタイプであり、本格的な機能開発ではなく、設定値の変更による成果物の変化を検証することを主眼とする。
* チーム定義（メンバー、プロンプト、トポロジー）は `configs/teams/` に YAML ファイルとして一元管理し、コード変更なしに実験・比較が可能な構成とする。

## アプリケーションの挙動

* ユーザーは、事前にチームを定義する。
  * チームには、複数のメンバーが含まれ、メンバーには `id`, `name`, `prompt`, `tools` が含まれる。
    * `id` は、チーム内のメンバーでユニークであれば良い。
    * `name` は、そのメンバーを表す名称を自由に設定できる（例: CEO、CFO）。
    * `prompt` は、そのメンバーの挙動を指示する、LLM用のプロンプトを表す。
    * `tools` は、そのメンバーが利用できるツールを表す。
  * チームには、各メンバーがどのようにお互いに議論をするか、そのコミュニケーションの仕方を規定するトポロジーを定義することができる。

* ユーザーは、コンソールで、事前に定義された複数のチームのうち、どれを選ぶか選択する。

* ユーザーは、コンソールで、選択したチームに議論してほしい議題を入力することができる。

* 議題を入力すると、指定チームの各メンバーが議論をはじめ、その議論の結論と各メンバーの発言履歴が列挙された、レポートが `outputs/` ディレクトリ配下に出力される。

### トポロジーの例

以下は、新規事業構想チームにおけるトポロジーの例である。段階的にメンバーを増やしながら検証を深める構造をとる。

| Phase | 参加メンバー | 目的 |
| --- | --- | --- |
| Phase 1 | CEO, CMO | 楽観的に初期の事業アイディアをブレスト |
| Phase 2 | CEO, CMO, CFO | Phase 1 の結果に対して売上計画の現実性を検証 |
| Phase 3 | CEO, CMO, CFO, CTO | Phase 2 の結果に対して技術的な実現性を検証 |
| Phase 4 | CEO, CMO, CFO, CTO, 反証担当 | Phase 3 の結果に対して各仮説の反証に耐えうるか検証 |

* 各 Phase で検証に耐えられるアイディアがなければ、前の Phase に戻りアイディアを強化する。
