# 議論フロー仕様

本ドキュメントでは、チームの議論がどのように実行されるかの仕様を記述する。

## 全体の流れ

```
チーム定義 YAML 読み込み
  ↓
Phase 1 実行
  ↓ Phase 1 の結論を生成
Phase 2 実行（Phase 1 の結論を引き継ぎ）
  ↓ Phase 2 の結論を生成
  ...
Phase N 実行（Phase 1〜N-1 の結論を引き継ぎ）
  ↓ Phase N の結論を生成
  ↓
全体の結論を生成（Phase 1〜N の結論を基に）
  ↓
レポート出力
```

## Phase 内の議論

### 発言順序の決定ルール

各 Phase の発言順序は以下のルールで自動的に決定される。

1. **新規参加者が先頭** — 前の Phase には参加しておらず、今回の Phase で新たに加わったメンバー
2. **既存メンバーが後続** — 前の Phase にも参加していたメンバー

これにより、新たな専門的視点が先に提示され、既存メンバーがそれを踏まえて議論できる。

### ラウンド制

* 1ラウンドで全参加メンバーが発言順序に従い1回ずつ発言する。
* これを `rounds` 回繰り返す。
* 各メンバーは発言時に、当該 Phase 内のそれまでの全発言を参照できる。

### 具体例

```
Phase 1 (CEO, CMO):          ※ 全員が新規
  Round 1: CEO → CMO
  Round 2: CEO → CMO

Phase 2 (CEO, CMO, CFO):     ※ CFO が新規参加
  Round 1: CFO → CEO → CMO
  Round 2: CFO → CEO → CMO

Phase 3 (CEO, CMO, CFO, CTO): ※ CTO が新規参加
  Round 1: CTO → CEO → CMO → CFO
  Round 2: CTO → CEO → CMO → CFO
```

## Phase 間の情報引き継ぎ

### 結論ベースの引き継ぎ

各 Phase の終了時に、LLM がそのフェーズの議論内容を要約し「Phase の結論」を生成する。次の Phase のメンバーには、前フェーズまでの結論が引き継がれる。

```
Phase 1 の議論 → Phase 1 の結論を生成
                    ↓
Phase 2 のメンバーに「Phase 1 の結論」を提供 → Phase 2 の議論 → Phase 2 の結論を生成
                                                                    ↓
Phase 3 のメンバーに「Phase 1 の結論」「Phase 2 の結論」を提供 → Phase 3 の議論 → ...
```

### 設計意図

* **生の発言履歴をそのまま渡さない** — Phase が進むほど会話履歴が膨大になり、トークン上限の圧迫や要点の希薄化が起きるため。
* **結論を要約して引き継ぐ** — 新規参加者が要点に集中でき、トークンの効率も良い。
* **当該 Phase 内の発言はリアルタイムで共有** — 同じ Phase 内では全発言が蓄積され、後続の発言者が参照できる。

## 結論の生成

### Phase の結論

各 Phase の終了時に、以下の構成で結論が要約される。

1. このフェーズの結論（合意事項・決定事項）
2. 主要な論点と各メンバーの見解
3. 次のフェーズに引き継ぐべき課題

### 全体の結論

全 Phase の終了後、各 Phase の結論を基に以下の構成で全体の結論が生成される。

1. 議論の最終結論（最も重要な合意事項や決定事項）
2. 各フェーズで得られた主要な知見
3. 残された課題やリスク

## レポート出力

議論の結果はマークダウン形式のレポートとして `outputs/` に出力される。

### レポートの構成

```
# 議論レポート: {チーム名}
  議題

## チーム構成
  ### メンバー一覧（テーブル）
  ### トポロジー（テーブル）

## 結論（全体の結論）

---

## 議論の詳細
  ### {Phase 名}
    #### このフェーズの結論
    #### Round 1
      ##### {メンバー名}: 発言内容
    #### Round 2
      ...
  ### {次の Phase 名}
    ...
```

### ファイル名

`{チーム ID}_{タイムスタンプ}.md`（例: `startup_team_v1_20260221_193000.md`）
